## Lifecycle and agreement

`Shared::end` remains the sole first-cause transition owner: its state mutex refuses later cause replacement, takes pending RPC senders, settles them, and publishes the existing watch. `Connection::send_frame` selects that publication (biased first) against ordinary queue admission; both call and notify use the same private bridge. A live call blocked acquiring an ordinary permit, or blocked on physical FIFO capacity after acquiring one, can now return the retained terminal cause while the custom writer remains held. An already-published end wins against an immediately writable empty queue. The watch bridge adds no second close flag, semaphore-close controller, pending-response shortcut, or priority scheduler.

`Pending.sent` becomes true only after successful enqueue, in the same poll continuation. Terminal selection drops the losing admission future and its encoded frame/owned permit. On a pre-enqueue terminal result, Pending Drop cannot fabricate cancellation: sent remains false and Shared end has already retired the pending ID. Normal enqueue/reply/drop semantics are preserved; an answered call clears the guard ID, cancellation of a sent pending call separately cancels its local POST reader and tries its ordinary best-effort remote notification. No response oneshot is selected to authorize success before admission. Concurrent end/watch publication and enqueue are not an atomic commit; the change does not promise universally zero enqueue after state termination.

`OutgoingQueue` owns one mpsc FIFO and one ordinary semaphore. Ordinary Frame envelopes retain permits until dequeue; partial movement of the message drops the remaining permit before dispatch. Failed send/try_send and dropped admission futures also drop the permit. Receiver teardown drops queued permits and wakes physical waiters; those release held permits so semaphore waiters can observe the closed sender. HTTP derives 65 physical slots from 64 ordinary plus one reserved slot; stdio keeps 64 plus zero. PeerReply and RecoveryReady bypass ordinary admission but retain the same bounded FIFO, including controls using otherwise free physical capacity. Cancellation notifications remain ordinary frames.

Reader HTTP control Full produces typed TooLarge and Closed preserves state cause or ServerGone. `read_messages` raises HttpSession shutdown before Shared publication. Writer End likewise shuts down before end. Shutdown owns the closing fence, joins registered readers/startup, and owns DELETE only for a retained binding claim. Dispatch/modern_request recheck the HTTP owner around async authorization; queued replies preserve their captured binding/version. Existing close ordering (Shared publication then synchronous HTTP shutdown/abort) is unchanged. This review distinguishes admission cancellation from the HTTP downstream effect fence; the biased select is not presented as an atomic effect fence.

RecoveryReady remains inside the startup task's existing `within(deadline, startup)` covering both queue admission and completion. Shutdown aborts/joins that registered startup. `finish_recovery` checks deadline/phase/completion receiver, bounds sending by the same deadline, and synchronously validates completion before reopening recovery. No new allowance or ownership escape was added.
