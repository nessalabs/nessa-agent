## Adversarial lifecycle conclusions

`Shared::end` is the sole terminal-cause decision owner. It commits the first cause and takes pending under State mutex, releases that mutex, publishes existing watch, then wakes pending response channels. Competing end calls cannot replace the first commit or publish another cause. HTTP close, HTTP writer End and read_messages all raise HttpSession shutdown before Shared end; explicit close now does so even before the State commit. HttpSession's existing closing flag and reader/phase coordination fence downstream POST/handoff effects and retain one cleanup claim. First cause means first State commit, so a reader/writer cause can legitimately beat explicit close after close raises the HTTP fence.

`send_frame` creates its watch subscription synchronously before taking the retained-State snapshot. A recorded end therefore rejects immediately even if publication is stalled by a borrowed watch value; an end after an open snapshot is retained by watch and has biased selection over admission once published. Watch `wait_for` also checks its initial retained value, so reversing subscription alone is not presented as a proven lost-wake bug. Checked-open admission may race queue insertion after end commits; this is expressly documented rather than falsely claimed atomic. HTTP dispatch still fences the resulting effects. Stdio remains reserve0 with its existing writer-abort semantics; no new universal atomic enqueue or stdio external-effect guarantee is claimed.

Both ordinary semaphore waits and physical FIFO waits are cancellable under the same terminal selection. Queue envelopes own permits until dequeue/drop; taking the message drops the remaining permit field before dispatch, and failed send mappings drop the envelope. Cancellation before insertion drops the owned permit/frame, and receiver drop releases queued permits and causes physical sends to fail. Pending guards remove correlation and only attempt remote cancellation when admission actually completed. Local HTTP cancel_post remains independent of the best-effort remote cancellation frame. RecoveryReady has no ordinary permit but remains physically bounded, FIFO ordered, and subject to its existing total startup budget and completion validation.

Control admission never awaits in the reader. HTTP Full is typed TooLarge, Closed returns retained cause or ServerGone, and reader termination raises the same HTTP fence and cleanup path. Stdio best-effort peer replies remain ordinary frames and preserve the prior drop-on-full behavior. Ping and unsupported methods share the captured PeerReply context; initialization does not retroactively alter SID/version. The tests distinguish answer admission, actual answer POST, initialized completion and later ordinary acceptance.

The synchronous-waker boundary is honest: publication occurs outside State mutex, allowing State reentry. `contain_caller_wake` catches public caller waker panic/destruction, not arbitrary blocking; public MCP waits in servers.rs use it and keep_listed is spawned with a Tokio task waker. New admission watches therefore do not introduce an uncontained public panic path. A custom blocking watch waker can delay subsequent pending drains; a raw crate-private panicking watch waker can unwind after State/watch commit and cause remaining oneshot receivers to fall back to ServerGone. Those are explicit unsupported arbitrary-callback guarantees, not a claimed generic containment repair. I found no reachable newly introduced public regression within the stated contract. The existing Closed receiver regression intentionally demonstrates #670 and remains useful evidence of typed queue loss.
