## Finding N1 — nit — qualified error type names in new queue wrapper

Source: `crates/nessa-sdk/src/infrastructure/mcp/connection.rs:151,155,166,173–195,207` (same head). New signatures repeatedly name `mpsc::error::SendError`, `TrySendError` and `TryRecvError`; bodies repeat these qualified type paths as constructors/patterns.

Trigger/proof: inspecting the new wrapper directly is sufficient; no runtime input is required. `CODING_STANDARDS.md:570–578` says “Import types at the top of the owning file or module, then use their short names in signatures, implementations, and expressions,” permitting conventional qualified module functions/macros instead. The introduced error-type paths are types, so that exception does not apply. Expected: grouped module-top error imports and short names in new signatures and expressions. Actual: repeated qualified error types. Suggested disposition: import SendError/TrySendError together, and guard the TryRecvError import with the same `all(test, unix)` condition as its only use. This is style/organization evidence, not a transport correctness defect. No claim that all existing qualified paths in unchanged code belong in this fix.

## Adversarial lifecycle inspection

* **Cancellation before and after permit acquisition.** `OutgoingQueue::send` (connection.rs:147–166) holds no ordinary permit before acquire completes; after acquisition the permit is owned by the local/enqueued `Queued`. Cancelling while waiting on physical capacity drops that envelope and permit. J24 explicitly polls and drops both a permit waiter at ordinary saturation and an acquired-permit send behind two controls, then admits another ordinary frame. It proves both stages rather than relying on eventual test completion. Pending::drop (connection.rs:475–508) still removes the exact RPC ID, directly aborts local HTTP POST reading, and only then attempts best-effort remote notification. Queue admission of that notification does not authorize the local cancellation or claim upstream acknowledgement.
* **Dequeue/failed-send/teardown release.** `recv` (connection.rs:201–208) moves only `message`; the remaining OwnedSemaphorePermit drops before the writer sees the returned frame. J24 holds that returned frame while another frame admits, making dispatch-time release falsifiable. Error conversions move the message out and drop the remainder of Queued, releasing acquired permits on Full/Closed. Receiver teardown drops queued envelopes and wakes physical sender waiters; those waiters release their permits in the error mapping, allowing remaining semaphore waiters to wake and observe Closed. No semaphore-close requirement is introduced: permit release comes from owned envelopes and rejected pending sends. The teardown test has 64 ordinary envelopes and a blocked ordinary sender when dropping the receiver, and asserts rejection. No newly introduced retained permit cycle found.
* **Exact admission and FIFO.** ordinary64 + reserve1 is derived once in `new` (136–143); stdio supplies reserve0 (243), HTTP reserve1 (293). Outgoing::is_ordinary exhaustively makes Frame ordinary and both PeerReply/RecoveryReady controls. Sender clones share one Arc semaphore and FIFO. Controls can occupy otherwise free ordinary slots, but cannot exceed the physical65 bound. Ordinary futures waiting behind controls already own permits, so “64” includes those retained sends. No priority or unconditional progress is promised. J21 holds an actual writer exchange, polls64 real calls plus a dropped excess, injects ping and unsupported request separately and waits for a trailing notice to prove reader progress. J22 injects matching initialize before releasing the writer and checks peer answer precedes notifications/initialized.
* **Overflow and actual closure.** deliver (connection.rs:566–590) propagates Full as typed TooLarge and Closed as retained Shared cause or ServerGone. `read_messages` (624–650) synchronously raises HttpSession shutdown before Shared.end. J23 asserts overflow cause, surviving later close, no queued answer exchange, one DELETE and startup reader destruction. The Closed case injects a real custom-exchange writer panic, first demonstrates no pre-existing end publication, then submits a peer request to the actually lost receiver; it asserts ServerGone and cleanup. This does not claim the panic itself is supervised.
* **Competing causes and shutdown.** Shared.end (64–79) uses one mutex-protected first cause, drains pending IDs once and publishes that cause. Reader overflow fences the HTTP owner before publishing end; a writer awakened later must inspect that fence. writer SendOutcome::End (connection.rs:316–333) likewise shuts down before ending. Explicit close (456–462) ends then invokes synchronous shutdown and aborts writer; no await can intervene. HttpSession::shutdown (http.rs:267–330) sets closing under reader-registration ownership before checking the one cleanup claim. The unchanged `http_shutdown` regressions specifically assert a second shutdown caller cannot skip the fence and repeated calls produce one DELETE/release claim. New J23/J25/J26 verify retained TooLarge/Timeout/Closed/Unauthorized with later different close causes and no answer/initialized effects. Source mutex arbitration covers same-poll competing ends; the new tests mostly force separated causal orders, while existing J11–J13 cover completion/deadline commit races. I did not execute a new simultaneous-ready runtime probe.
* **Phase budget and stale binding.** The RecoveryReady send and completion await remain inside `within(clock, deadline, startup)` (http.rs:1024–1034), and finish_recovery validates phase/deadline/completion before send and commit (1055–1158). No queue wrapper adds an independent timeout or resets the phase budget. J25 advances the inherited initialization deadline while the answer is queued and proves no later reply/initialized effect. ReplyContext is unchanged and moved through the envelope; modern_request (http.rs:562–639) uses captured binding/version, check_reply_binding (1533–1542) rejects a different Arc or failed recovery, and existing authorization rechecks continue to fence effects. J21/J22 assert exact originating replacement SID and absence of a negotiated version on the earlier reply even after matching initialize is consumed; succeeding ordinary call is the positive control.
