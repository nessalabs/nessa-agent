## Findings and correction

At `connection.rs:465`, generated peer answers still use best-effort `outgoing.try_send`. A full 64-frame ordinary writer queue can discard a required early peer answer, and a server waiting for that answer can stall recovery until its initialization deadline. Expected control availability under ordinary queue pressure is not established by the unsaturated early-ping tests. This is the already acknowledged P2 #665, not a new finding or an authority escape. The recovery deadline, retained startup ownership and shutdown fence still bound local consequences. Do not describe this PR as fixing queue-pressure control delivery.

`http.rs:266` now acquires the reader registry and stores `closing=true` before consulting `delete_started`. Consequently every shutdown caller establishes the effect-admission barrier before returning, including a loser while another caller has claimed cleanup. The winning caller drains handles inside that fence and releases it before aborting, phase capture, joins or spawning cleanup. Publication, reply-context creation, modern request construction, recovery registration and handoff completion acquire the same registry before checking closing. There is no reverse phase-to-registry nested lock path in the reviewed production owner.

The owning `http_shutdown.rs` regression seeds the old reachable claimed-cleanup/before-closing state and calls actual second shutdown. It then supplies a valid initialize result and valid JSON notification, asserting Closed, no publication/binding/GET, an available claim for the would-be ID and no POST. Its separate positive control calls shutdown repeatedly and checks one DELETE, finished=true and claim release. The test deliberately stages the old state; it does not claim to produce that state under the fixed implementation.
