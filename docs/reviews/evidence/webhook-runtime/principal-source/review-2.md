## Agreement, enforcement and ownership

**Authority and selector ownership.** `PrincipalRecordScope` contains registration/principal/organization/owner/conversation/epoch facts with private fields and typed identities; it is selector data, not a permission token. It does not create `ReceiverReadScope` or paired-reader authority. The current admission owner remains unchanged: actual credential hold and credential/principal/organization/audience/membership/lifetime correlation, then exact principal/resource grant revision hold, actual metadata and existing WebhookReader Cedar decision. Receiver ID must be absent from that principal grant. The source port is called only after this gate. Composition is explicitly responsible for supplying the actual committed private registration and shared canonical limits/budget; no product mounting is claimed.

**Original resources, not returned claims.** The corrected use case places the actual `DeliveryHold` and the actual successful `OwnedSemaphorePermit` together in one `Arc<Mutex<...>>`. The application retains that owner independently of the response, while the physical read receives a lease carrying the same owner. A valid response whose opaque lease is replaced, absent in substance, or unrelated cannot release the original application-owned budget/fences. The regression decorates an actual canonical native read, substitutes only its returned lease, and now passes while the retained result keeps capacity unavailable. Validation/error exits drop the application copy; any still-owned physical copy remains until original physical cleanup. The trusted physical port still must carry the supplied lease through its work; the reviewed native adapter does so. This is not a sandbox against arbitrary malicious native implementations starting untracked work.

**Acquisition and cancellation.** Acquisition is nonblocking shared-capacity reservation, then Auth hold, principal grant hold, metadata/Cedar, native bookkeeping, SDK identity/source work. No worker lock is held while acquiring authority. The new inspection mutex only protects the retained owner, crosses no await, and is never acquired by physical work; no reversed new acquisition edge was found. Before-grant cancellation drops original capacity and acquired Auth ownership. After physical handoff, observer loss sets the existing stop flag and the native closure retains the original lease. Actual source drop joins SDK work; ReadWorkers tracks OS joins and unobserved panic, and retains shutdown completion independently of cancelled shutdown observers. Tests exercise normal and panicking physical work plus real pending revoke/unshare fences. Source shutdown drains native work; it is not a claim that an unimplemented command coordinator drains pre-admission futures or retained results.

**Expiry and data access.** Admission rechecks lifetime before returning its hold; result construction and each `value()` inspection recheck absolute expiry, which a mutation fence cannot suspend. Expiry during native work refuses the result. A borrowed page is data already read, not future send authority. Future queue/sender composition must retain its relevant ownership and independently admit each physical attempt. Long-term retained-result lifetime is an eventual bounded coordinator responsibility, explicitly unimplemented here.

**Request, physical and response correlation.** Principal selectors use the existing registration UUID consumer representation and epoch encoding expected by outbox storage. Wrong requested registration/conversation/epoch and invalid page bounds refuse before source invocation. Both concrete reader entries share existing SDK discovery and worker limits; the receiver entry retains its original opened-source validator. Actual physical scope comparison covers origin/stream/incarnation/schema and the requested conversation/consumer/epoch. Returned variant/request/selector must match the original request, and canonical sync validation owns page positions, payload bounds and record scopes under composition-selected limits, not adapter-supplied limits. The real native adapter bounds physical work and joins source cleanup. No duplicate Cedar rule, new policy action, protocol/SDK/client shape, schema, credential mode or global configuration is added.

**Persistence and no-effect boundaries.** Negative tests use real synthetic Auth/Cedar/grants and assert no source invocation or unchanged actual cursor/delivery/audit counts as appropriate. Retained stale selectors cannot survive unshare/regrant into a current read.
